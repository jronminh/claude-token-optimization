# Token efficiency

- **Large files**: check size before reading (`ls -la` / `stat -c%s`). Under 50KB, read normally. From 50KB up, prefer `grep -n` (or `rg`) first to locate the relevant lines/region — only read the file directly (fully or in chunks) when grep genuinely can't answer the need. At or above 100KB, never read the whole file in one shot regardless — grep to find the region, then Read with `offset`/`limit` for just that part. For `.md` files specifically, `check-md-size.sh` already warns live at token-based thresholds — don't skip the manual check on other file types just because this one's covered.
- **Repeated reads of the same file within a session**: prefer `grep -n -A<N> -B<N> <anchor>` over a full re-Read when you already know the file's content from earlier this session, unless many turns have passed or it may have changed elsewhere. `check-reread.sh` warns live the moment you `Read` a file already read this session — when you see that warning, act on it.
- **Reasoning/output**: be concise and direct. No restating the question, no filler recaps, no multi-paragraph explanations unless asked for depth.
- **CLAUDE.md size guard**: `check-md-size.sh` warns on Edit/Write to this file once user-editable content exceeds ~1000 estimated tokens — prune or merge existing bullets before adding new ones.
- **Context monitoring is automatic**: `context-monitor-hook.sh` checks real token usage every 15 tool calls and notifies once per checkpoint crossed (100k, 200k, 300k...). It deliberately reports no %/window — that can't be derived from the transcript. When you see that note, tell the user directly, name the heaviest calls via `find-large-turns.sh`'s output, and suggest they run `/context` for the real number before deciding on `/compact`.
